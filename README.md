# 오늘, 내일 — 자기주도 학습을 돕는 웹 플랫폼

포모도로 기법으로 작업에 집중하고, 음악을 들으며 학습 목표를 세우고,
일지와 통계로 진행 상황을 확인하는 자기주도 학습 웹 플랫폼입니다.
2025년 3~4월, 6명이 기획부터 5주간 진행한 JSP 팀 프로젝트입니다.
(커밋 기록은 구현 단계인 3월 31일 ~ 4월 17일에 집중돼 있습니다.)

> 이 저장소는 팀 원본(`Dingrrrr/2025_JspProject`)의 포크입니다.
> 저는 **97커밋으로 팀 내 2번째 기여자**이며, Pull Request 기반으로 협업했습니다.

## 내가 맡은 부분

### 작업 목표(Objective)

집중 타이머로 무엇을 할지 정하고, 달성을 체크하고, 지난 목표를 보관하는
목표 관리 기능을 담당했습니다.

- **목표 등록·수정·삭제·달성 체크**
  (`ObjInsertServlet`, `ObjUpdateServlet`, `ObjDeleteServlet`, `ObjCheckUpdateServlet`)
- **그룹 분류** — 목표를 그룹으로 묶어 관리하고 현재 그룹을 전환
  (`ObjGroupBean`, `ObjCurrentGroupSetServlet`, `insertObjGroup.jsp` 외)
- **보관함** — 지난 목표를 아카이브해 따로 조회
  (`ObjArchivedListServlet`)

> 목표 달성 통계 그래프(`objTotalGraph*`)는 다른 팀원이 이 기능 위에 추가한 것입니다.

### 구글 OAuth 로그인

외부 인증 제공자를 연동해, 계정을 새로 만들지 않고 구글 계정으로
로그인할 수 있게 했습니다. (`GoogleLoginServlet`)

### 알림 · 공지

서비스 내 알림과 공지 기능을 담당했습니다.
(`NotifiBean`, `NotifiMgr`, `AncBean`, `AncMgr`)

## 해결한 문제 — 새로고침해야 보이던 목록

목표를 추가하면 서버에는 정상 저장되는데 **새로고침을 해야 화면에 나타났습니다.**
기능은 동작했지만, 집중해서 작업하는 도중에 화면을 새로 고쳐야 한다는 건
이 서비스의 목적과 어긋나는 흐름이었습니다.

화면을 다시 그리는 시점을 페이지 로드가 아니라 **사용자가 버튼을 누른 시점**으로
바꿔, 추가·수정·삭제가 즉시 화면에 반영되도록 수정했습니다.
기능이 되는 것과 자연스럽게 쓰이는 것은 다른 문제라는 걸 이때 배웠습니다.

## 팀 전체 기능

| 영역 | 내용 |
|---|---|
| 집중 타이머 | 포모도로 타이머, 사용자별 기록 |
| 작업 목표 | 목표 등록·체크·그룹 분류·보관함 (+ 달성 통계 그래프) |
| 저널 | 작업 일지 작성·수정·삭제 |
| 회원 | 회원가입·로그인, 이메일 인증코드 발송/검증, 구글 OAuth 로그인, 비밀번호 찾기 |
| 배경음악 | 음원 업로드, 재생목록 관리, 켜기/끄기 |
| 테마 | 테마 이미지 업로드·적용·해제 |
| 공통 | 알림, 공지 |

## 기술 스택

- **Java** Servlet / JSP (자바 파일 296개)
- **MySQL** — `DBConnectionMgr`에 커넥션 풀 직접 구현
- **JavaScript / CSS**
- Google OAuth, 메일 발송(인증코드), 파일 업로드(멀티파트)

## 실행

MySQL에 `jspproject` 스키마가 필요하며, 접속 정보는
`myapp/src/main/java/jspproject/DBConnectionMgr.java`에 설정되어 있습니다.
